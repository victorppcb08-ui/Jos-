# Auditoria — Reabilitação Administrativa da Sanção de Inidoneidade

Pasta de trabalho da **complementação de auditoria de compliance** referente ao
pedido de **reabilitação administrativa** da sanção de **declaração de inidoneidade**,
nos termos do **art. 163, inciso III, da Lei nº 14.133/2021**, regulamentado pelo
**Decreto nº 12.304/2024** e pela **Portaria Normativa SE/CGU nº 226/2025**.

A avaliação técnica aplica o **Formulário de Conformidade** previsto no **Anexo II**
da Portaria SE/CGU nº 226/2025, composto de **113 questões** organizadas em
**12 áreas temáticas**, das quais **16 são questões críticas** — cujo resultado
negativo constitui, *per se*, hipótese autônoma e independente de indeferimento.

> **Fase atual:** o interessado apresentou **documentação adicional**. O objetivo
> desta etapa é reavaliar as questões respondidas anteriormente como **NÃO** ou
> **PARCIALMENTE**, verificando se foram **superadas** pela nova documentação.
> As questões já respondidas como **SIM** são mantidas (com checagem de consistência).

## 📤 Como subir os documentos para esta pasta no GitHub

**Opção A — pela interface web do GitHub (mais simples):**
1. Abra o repositório no GitHub e selecione a branch `claude/auditoria-compliance-plan-0o9tah`.
2. Navegue até a subpasta desejada (ex.: `Auditoria_Reabilitacao_Inidoneidade/03_Documentacao_Nova`).
3. Clique em **Add file → Upload files**.
4. Arraste os arquivos e clique em **Commit changes**.
   - Para subir vários de uma vez, arraste todos juntos. Para criar subpastas
     dentro de `03_Documentacao_Nova`, basta digitar o caminho no nome do arquivo.

**Opção B — quando terminar de subir, me avise aqui.** Eu leio os documentos
diretamente do repositório e inicio a auditoria conforme o
[Plano de Trabalho](./PLANO_DE_TRABALHO.md).

> 💡 Dica: nomeie os arquivos novos de forma que ajude a rastreabilidade —
> por exemplo, prefixando com a área/tema ou com o número da questão que o
> documento pretende comprovar (ex.: `Q045_codigo-de-conduta_v2.pdf`).
